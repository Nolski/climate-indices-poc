# Changes to the API contract

History of changes since the first draft of the contract ("v0"), newest last. The current state
of the API is described in [api-contract.md](api-contract.md). Every change so far is an
addition or a clarification: nothing in v0 was removed or renamed.

| # | Where | Change | Why |
|---|---|---|---|
| 1 | Dataset object | Added `qc.settings` (the QC thresholds used) and top-level `notes` (non-fatal parser notes such as a skipped header line; each `{line, code, message}`). | QC can be re-run with other thresholds; the UI needs to show what was used. |
| 2 | Dataset object | `qc.summary` counts **checks with at least one finding** per severity, not findings. | v0 did not say which; with 395 outliers a count of findings would be misleading as a headline. |
| 3 | Dataset object | Dataset ids are `ds_` plus 16 hex characters (v0 showed 6). | The id is the only thing protecting a dataset; it must not be guessable. |
| 4 | `GET /api/indices` | Added `validation` (`{"annual": "exact", "monthly": "exact"}`: the status of each compared output in `VALIDATION.md`). `validated` is true only when every frequency was compared with the R baseline **and agrees**; `gsl` is false because its missing-value mask differs in one year. | "Compared" alone would label a differing index as validated. |
| 5 | `GET /api/indices` | 48 indices are listed (v0 named about 30). Units also include `degree-days`. | The threshold-count, degree-day and R95pTOT variants are single registry entries. |
| 6 | Errors | `details` items are objects: `{line, code, message}` for `invalid_station_file`, `{field, message}` for `invalid_request`; for `unknown_index` the unknown ids as strings. | v0 said only "details: [...]". |
| 7 | Errors | Codes in use: `invalid_station_file` (422), `invalid_request` (422), `empty_file`, `invalid_base_period`, `unknown_index`, `no_indices`, `unknown_variable`, `invalid_date`, `unknown_missing_policy`, `invalid_missing_policy`, `unknown_qc_setting`, `nothing_to_export` (all 400), `dataset_not_found`, `sample_not_available`, `not_found` (404), `method_not_allowed` (405), `file_too_large` (413). | Stable codes for the UI's messages. |
| 8 | New endpoint | `POST /api/datasets/{id}/qc` with a JSON object of any QC settings (for example `{"max_precip_mm": 150}`) re-runs quality control and returns the `qc` object; the stored dataset is updated. | Re-running QC with changed thresholds is a documented user request. |
| 9 | `POST .../compute` | Optional body fields `missing_policy` (`{"id": "climdex" \| "any" \| "fraction", ...limits}`) and `percentile_method` (`"climdex"` default, or `"xclim"`). | Shows the pluggable policy and the labelled, slower xclim-native percentile option. |
| 10 | `POST .../compute` | `trend` is also `null` when less than 70 % of the series is valid (v0: fewer than 10 values). `lower` and `upper` are per decade, like `slope_per_decade`. Monthly series: per decade = per step x 120. | The R tool's rule is 10 values and 70 %. |
| 11 | `POST .../compute` | Results are cached per dataset; a repeated request returns `elapsed_ms: 0`. Index values are rounded to 4 decimals, daily values to 2. | Faster UI; smaller payloads. |
| 12 | `GET .../export` | `format=json` returns the compute response as a file download. `frequency` accepts `annual` or `monthly`. When none of the requested indices can be computed the answer is 400 `nothing_to_export`. The zip also contains a tidy CSV, a NetCDF file, a trend CSV and a missing-days-per-year CSV. | Completeness. |
| 13 | Static files | Assets are served with `Cache-Control: public, max-age=604800` and an ETag; with a version in the URL (`app.js?v=3`) they are `immutable` for a year. HTML and `fixtures/` are `no-cache`. A Content-Security-Policy of `default-src 'self'` (inline styles allowed, inline scripts not) is sent. | Low bandwidth: repeat visits cost one conditional request per file, or none with versioned URLs. |
| 14 | Fixtures | `web/fixtures/` is regenerated by `scripts/make_fixtures.py` from the real API. Added `daily_tasmin.json`, `daily_pr.json`, `qc_rerun.json`, `error_unknown_index.json`, `health.json`. The first-pass fixtures (taken from R baseline files in the first minutes) were replaced. | Fixtures and reality match. |
| 15 | API docs | The OpenAPI schema is at `/api/openapi.json`. FastAPI's interactive documentation page is switched off because it loads its assets from a CDN. | Offline first: no external requests. |
| 16 | `POST .../compute` | Optional `parameters` object for the user-defined indices: `wsdi_days`, `csdi_days` (1 to 10), `hdd_base`, `cdd_base`, `gdd_base`, `rx_days`, `rnn_mm`. The identifier carries the value (`rx_days: 7` gives `rx7day`); the defaults give the identifiers of `GET /api/indices`. With non-default parameters, `"indices": "all"` returns the renamed identifiers and the default ones are unknown. | The R tool lets users set these; needed to compare the two tools with non-default parameters. |
| 17 | Index results | `gsl` is computed from the ETCCDI definition instead of xclim's `growing_season_length`; its Climpact-style CSV now has the columns `time, start, sl, end`. Values change only for records with a cold season. | Found by the cold-climate validation variant; see VALIDATION.md. |
| 18 | New endpoint | `GET /api/limits` returns `{max_upload_mb, max_datasets, dataset_ttl_minutes, rate_limit_per_minute}` (`rate_limit_per_minute` is `null` when off). | A separately hosted front end must show the real limits of the server it talks to. |
| 19 | Deployment | Limits are configurable by environment variable, validated at start-up: `CLIMPOC_MAX_UPLOAD_MB` (default 20), `CLIMPOC_MAX_DATASETS` (50), `CLIMPOC_DATASET_TTL_MINUTES` (60). Defaults are unchanged. | A small public server cannot hold 50 uploads of 20 MB in memory. |
| 20 | Deployment | Cross-origin access is off unless `CLIMPOC_CORS_ORIGINS` lists exact origins. Then: `Access-Control-Allow-Origin` echoes a listed origin (never `*`), no credentials, methods `GET, POST, DELETE, OPTIONS`, request header `Content-Type`, exposed headers `Content-Disposition` and `Retry-After`, preflight cached 10 minutes. Error answers carry the headers too. | The public demonstration serves the front end from another origin. |
| 21 | Deployment | Optional request limit: `CLIMPOC_RATE_LIMIT_PER_MINUTE` (default 0, off) per client address on `/api/` except `/api/health` and preflight requests; answer `429` with code `rate_limited` and `Retry-After`. `CLIMPOC_TRUST_PROXY=1` takes the address from the last entry of `X-Forwarded-For`. | Basic protection for a public demonstration behind a reverse proxy. |
| 22 | Front end, cross-origin use | No endpoint changes. The same `web/` can now be published as a static site (GitHub Pages) that calls a separately hosted API named in `web/config.js` (`scripts/build_pages.sh` writes it and adds that origin to the page's CSP `connect-src`). What the front end sends, and therefore what row 20 has to allow, checked against the API with `CLIMPOC_CORS_ORIGINS` set: methods `GET`, `POST`, `DELETE` (so `OPTIONS` must be answered on every `/api` path); one request header of its own, `Content-Type: application/json`; never cookies or credentials. Preflighted: `POST datasets/sample`, `POST .../compute`, `POST .../qc` (JSON), `POST /api/datasets` (multipart, because the upload reports progress) and `DELETE`. Not preflighted: all `GET`s. It reads `Content-Disposition` (export file names) and `Retry-After` (a 429 is retried after that many seconds). It now also calls `GET /api/limits` on load and shows the server's upload limit and retention time; a 404 there means the defaults of 20 MB and 60 minutes. Not used by the page: `parameters`, `missing_policy` and `percentile_method` on compute. Details in `docs/pages-hosting.md`. | The public link is a static site on another origin; if the CORS headers are missing the browser hides the API's answers and the page falls back to its demonstration. |
| 22 | Errors | An unexpected server error answers `500` with code `internal_error` in the usual error shape (and with the cross-origin headers when they are configured); the details are logged on the server, not sent. | A separately hosted page can then show a message instead of a network failure. |
